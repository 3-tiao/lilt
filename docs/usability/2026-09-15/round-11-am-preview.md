> 你的人设：你的 Mac 登录了 Apple 账号，但没有 Apple Music 订阅。朋友说 lilt 这个终端 app「能搜 Apple Music 的歌，没订阅也能试听片段」。你不知道它会以什么方式告诉你限制。

## Agent 报告（原文）

# Round 11 报告：无订阅的 Apple Music 试听用户

## 时间线
1. 启动应用 → 首页显示 Apple Music、最近播放、歌单；底部为 `Nothing playing`。
   感受：初始界面清晰，知道可用 `/` 搜索。

2. `/` → 输入 `Bohemian Rhapsody` → `Enter` → 搜索结果出现，首项为 Queen。
   感受：搜索快，结果准确。

3. `Enter` → 出现队列和 Now Playing；状态为 `paused · Mode: full`，时长 `5:54`。
   `Space` → 等待 5 秒 → 状态变为 `playing`，进度到 `0:04`。
   `Space` → 状态变回 `paused`，进度约 `0:09`。
   感受：播放/暂停实际正常，但作为无订阅用户，我没有看到“试听”“预览”或时长限制，反而明确写着 `Mode: full`。

4. `?` → 帮助弹层显示 `f favorite / unfavorite`、`i track info` 等快捷键。
   `Escape` → `f` → 歌名前出现 `★`，底部提示 `★ Favorited: Bohemian Rhapsody`。
   感受：收藏动作反馈即时、明确。

5. `2` → 歌单列表；`Down Down Down Enter` → 打开“喜爱歌曲”。
   `F` → 输入 `Bohemian Rhapsody` → `Enter` → 显示 `0` 条和 `(no match for Bohemian Rhapsody)`。
   感受：虽然刚显示“已收藏”，但我无法在“喜爱歌曲”中验证它，造成困惑。

6. `Escape` → `i` → 信息弹层显示标题、艺人、ID、状态、`Mode full`、`Auth authorized`、播放位置、队列等。
   感受：基本播放信息有用；ID、授权和队列内部信息对普通用户帮助有限，且仍没有订阅/试听说明。

7. `Escape` → `/` → 输入 `Billie Jean` → `Enter` → 找到 Michael Jackson 首项。
   `Enter` → `Space` → 初始一度显示 `Now Playing · starting…`、`State: paused · … · working…`；等待后显示 `playing`、约 `0:08`。
   `Space` → 显示 `paused`、约 `0:09`。
   感受：上一首已被 Billie Jean 替换，播放和暂停正常；但启动期间“paused”和“working”同时出现，含义不够直观。

8. `q` → 应用退出，tmux 会话自行结束；未操作其他会话或进程。

## 发现的问题
1. **高：无订阅用户完全不知道自己播放的是试听还是完整歌曲，且界面明确声称为完整播放。**
   最小复现：`/` → `Bohemian Rhapsody` → `Enter` → `Space`。
   现象：Now Playing 显示 `Mode: full`、完整时长 `5:54`，信息弹层还显示 `Auth authorized`，没有任何“预览/试听/订阅限制”提示。对无订阅用户而言，这与预期强烈冲突。

2. **中：收藏成功提示与“喜爱歌曲”列表验证结果不一致。**
   最小复现：搜索歌曲 → `f` → `2` → 定位“喜爱歌曲”并打开 → `F` → 输入歌名 → `Enter`。
   现象：先显示 `Favorited` 和星标，但“喜爱歌曲”筛选为 0 条。用户无法确认收藏去了哪里，或是否真的成功同步。

3. **中：第二首歌启动时状态表达矛盾。**
   最小复现：搜索第二首歌 → `Enter` → `Space`。
   现象：显示 `starting…`、`working…`，但同时写 `State: paused`；随后才进入 playing。用户会不确定播放命令是否生效，容易重复按键。

4. **低：面向普通用户的信息弹层偏技术化，且没有解释关键限制。**
   最小复现：播放歌曲后按 `i`。
   现象：有 ID、Auth、队列索引等技术字段；最需要的“这是试听还是完整播放、可播放多久、为何受限”没有出现。

## 好的方面
- 搜索结果快且准确，常见歌曲容易找到。
- 当前播放、进度、队列和暂停/继续状态总体直观。
- `f` 收藏时有星标和即时 toast 提示。
- 换歌会正确替换当前曲目，队列也同步更新。
- 内置帮助覆盖了常用快捷键，便于终端用户探索。

## 改进建议
- 对无订阅或仅可试听的情形，明确显示“30 秒预览/试听”，附剩余时间和订阅说明；不要显示误导性的 `Mode: full`。
- 若实际权限或播放能力异常，应给出可理解的状态和下一步，而不是只显示 `authorized`。
- 收藏后明确说明收藏目标，并在“喜爱歌曲”中立即可见；若同步延迟，显示同步中或刷新入口。
- 将加载中的状态改为单一、明确的“正在开始播放…”，避免同时出现“paused”。
- 信息弹层优先显示专辑、发行年份、试听限制/音质等用户信息，将 ID、队列索引放到次级详情。

## 总体可用性评分（1-10）与一句话结论
**5/10**：搜索和基本控制可用，但无订阅用户最关键的“试听还是完整播放”完全不清楚，收藏验证也不可靠。

## 编排者复核（关键修正）

- **问题 #1 不成立（人设前提失实）**：agent 实测 `Mode: full`、完整时长 `5:54` 且真实完整播放——
  这台机器的 Apple 账号**实际有有效订阅**，应用如实显示 full。agent 因人设「无订阅」而将诚实显示判为误导。
  编排者设计人设时未先核实机器订阅状态，属测试装置错误。沉淀措施：涉及账号状态的人设必须先验证机器现实。
- **问题 #2 成立且升级为新发现（中）**：根因是两套「收藏」概念混淆——lilt 的 `f` 是**本地收藏**
  （存 state.json），而「喜爱歌曲」是 **Apple Music 资料库智能歌单**（MusicKit 侧），两者互不相通。
  更重要的真实缺口：Apple Music 来源**没有任何收藏列表视图**（amViews 无 Favorites），
  AM 歌曲收藏后无处浏览（只有星标）。属 AM 侧半成品功能，建议列入 backlog（补 AM Favorites 视图或
  帮助中说明 f 的本地性）。
- **问题 #3 成立（中低）**：MusicKit 启动瞬态 `starting…/working…` 与 paused 并存，helper 状态快照时序优化项，
  与 R6/R9 的 buffering 反馈问题同类。
- **问题 #4 成立（低）**：info 弹层技术字段优先级偏高，可重排。
