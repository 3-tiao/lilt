# Round 22 · Mouse second-click regression

- 日期：2026-09-16
- 终端：120×16，隔离 tmux / state / socket / log
- 模式：假播放器 + 真实 Radio directory
- 状态：完成；问题已修复并以真实终端鼠标协议验证

## 问题

Apple Music 主列表遵循“首次点击选中、再次点击播放”。旧渲染把选中行始终居中：首次点击较靠下的可见行后，列表立即滚动，第二次点击相同屏幕坐标落在另一首歌，导致误播。

## 最小复现与验证

1. 在 120×16 的 Radio Browse（100 项）中，初始窗口显示 `RTL`、`France Info`、`Europe 1`。
2. 对 `Europe 1` 的同一终端单元格发送鼠标左键按下事件。
   - 选中标记移动到 `Europe 1`；列表首行仍是 `RTL`。
3. 对完全相同坐标发送第二个左键按下事件。
   - Now Playing 显示 `Europe 1`；没有跳到下一项。

## 修复

主列表增加独立滚动锚点：鼠标点击保留当前可见窗口；只有键盘导航越出可见区域时才滚动。渲染、鼠标命中和 Radio probe 使用同一窗口计算。

## 回归覆盖

- 单元测试：在 3 行主列表中点击末行 `Three` 两次，必须打开 `Three`，而不是随后被重居中的 `Four`。
- 真实终端：SGR 鼠标事件验证两次同坐标点击播放 `Europe 1`。
