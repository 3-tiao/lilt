# 探索型 round 模板（无具体目标）

用途：版本迭代、重构或新 surface 上线后做宽泛走查。任务型只能覆盖已想到的路径；探索型用于发现
没有人写进任务的损伤。

探索型有两种方式，按成本从低到高：

| 方式 | 需要参与者 | 适合 |
|---|---|---|
| A · 编排者乱序发键 | 否 | 批量按键 + 帧巡检；只在异常时留证 |
| B · 探索型参与者 | 是 | 需要判断错位、困惑或状态与实际不符 |

一轮上限：**10 分钟或 300 次按键**，先到为准。

---

## 先做批次覆盖地图，再分配本轮格子

纯随机按键在 TUI 上覆盖极差：`j`/方向键会吞掉大多数输入，几百次之后仍可能在同一屏。覆盖地图是
**批次级到过清单**，不是本轮的目标；先列完整格子，再给每轮分配 3–6 个。

| 维度 | 格子例子 |
|---|---|
| 来源 × 视图 | Radio × 搜索结果；Apple Music × 歌单 |
| 弹层与临时态 | 帮助、搜索输入、命令面板、主题、加载、空列表、错误提示 |
| 尺寸 | 120×32、80×18、30×8；必要时运行中 resize |

批次 `index.md` 必须写每个格子的分配轮次、完成状态和未完成原因。不要要求一轮覆盖所有来源、弹层和
尺寸；那会让“10 分钟上限”失去意义。

---

## 方式 A · 编排者乱序发键

1. 编排者先按 skill 完成 `just verify && just build-go`、`preflight <batch> --fake-only`，再起 fake 装置：
   ```bash
   R=.agents/skills/usability-test/scripts/round.sh
   $R start fuzz --batch <batch> --fake --cols 110 --rows 30
   ```
2. 键池按权重取样：高频 `j k Up Down Tab Enter Escape`；中频数字键与视图切换；低频 `/ : s 0 c x J K f`。
   每次发 1–4 个键；至少 1/5 批次连发同一键 2–3 次。若用随机生成器，报告记录 seed；无论手工还是
   生成，脚本都会写完整序列到 `keys.log`。
3. 每批发完，等画面稳定并 capture：
   ```bash
   $R wait-steady fuzz j j j
   $R capture fuzz
   ```
4. 命中异常时，保留当时的 `keys.log` 和画面。不要用 `$R wait-frame-change` 判断按键是否有效；它只
   说明帧变化。

## 方式 B · 探索型参与者

把下面 prompt 中的 `<覆盖格子>` 换成本轮已分配的 3–6 格；不要把整个批次地图交给一个参与者。

```text
你是一名不了解本应用内部实现的独立体验者。本次没有具体任务：在分配的范围内自由操作，尝试暴露
错误、卡住、显示错乱或与实际不符的状态。全程使用简体中文。

你的人设：<一句话，例如“喜欢乱按、什么都想试一遍的终端用户”。>

你本轮要到过的范围（这是范围，不是操作指令；去那里做什么由你决定）：
<覆盖格子，每格用屏幕可见的说法描述。>

你的做法：
- 想到什么按什么，允许连续重复按同一个键、快速连按、在加载中途操作。
- 每次操作后看屏幕：有无错位、重复、残缺、边框破损、文字截断或与实际状态矛盾？
- 如果某次操作后长时间没反应，先等待，再记录键序、等候时间和屏幕事实。
- 如果界面完全无法继续，如实记录并停止。

环境（严格按此操作，不要改）：
- 编排者已经启动应用；不要启动、重编译、停止或杀掉进程。
- 命令入口：`R=.agents/skills/usability-test/scripts/round.sh`。
- 看屏幕：`$R capture <name>`；发键：`$R send <name> <键>`。特殊键：Enter、Escape、Space、
  Up、Down、Left、Right、Tab、BSpace、C-c。
- 节奏：单发或小批量按键后等待 0.5–1s 再 capture；加载后等待 2–4s；可用
  `$R wait-steady <name> <键...>` 发键并等待静止。**NOW PLAYING 已显示 Playing 或进度后，不要用
  wait-steady**：进度会持续变化；改用 `sleep 1` 再 capture。
- 本轮起始尺寸为 <cols>×<rows>；<若本轮含尺寸格子，写清 resize 到何种尺寸，并用 `$R resize` 执行。>
- 本轮音频：<静音轮：不会出声，只判断界面反馈 / 获批真实轮：会出声，播放验证后立即暂停或停止，总音频不超过 30 秒>。
- 若本轮为真实轮，不收藏、不修改资料库、不执行断开授权等账号操作；如需这些操作须编排者事先单独获批。
- 只操作 `<name>` 这个 round；绝不碰其他 tmux session 或 lilt/lilt-player 进程。

纪律（独立体验）：
- 严禁阅读仓库源码、文档、git 历史、README；只可使用应用内信息。
- 严禁读取 `/tmp` 下的日志或 state；一切结论只来自屏幕。
- 不要修改仓库或运行时文件。

结束流程：尝试像普通用户一样正常退出（可用 `$R send <name> q`）；无法退出则记录。不要运行
`$R stop`、tmux kill 或任何进程管理命令，编排者会清理装置。

报告格式（最终消息完整输出，由编排者写入本轮报告）：
# 探索报告：<人设>
## 覆盖情况
逐条列出本轮每个格子是否到达；没到达说明原因。
## 异常清单
逐条编号，标注严重度（高/中/低）。每条必须含：完整键序、屏幕事实（引用关键文案）、能否稳定复现。
## 做得好的方面
## 没法判断的地方
```

## 异常判据与复核

**算发现**（必须保留键序）：

- 崩溃、进程消失，或无法正常退出。
- 布局破损：边框缺失/错位、文字溢出、截断到不可读、重叠。
  **先排除装置假象**：`capture` 会回显 bubbletea 输出优化写入的 hard tab（跳过一串空格用 `\t`），
  于是在 capture 里表现为“某行比同行短、里面带 `\t`、边框看着断开”。真实终端会把 tab 展开为空格，
  帧本身是齐的（可用同一状态的 `View()` 输出核对）。这类不算布局破损。
- 状态与实际矛盾：显示“播放中”却没有进度、“已收藏”但列表为空、索引与高亮不一致。
- 同操作在已分配的不同尺寸或视图中行为不一致。
- 在稳定条件下，两个应有效操作都没有反馈，且 `$R status <name>` 显示 tmux/server 仍存活。

**不算异常**：设计不合口味、留白太多、“我觉得应该加功能”；这些进建议。上游 API 超时、网络抖动
不是产品 bug，但标为环境发现。

探索型产出默认是**待复现候选**：

1. 用干净装置重放同样键序；能复现才升级候选 bug。
2. 定位 TUI/server/helper/provider 层；有代码证据才叫 bug。
3. 汇总注明命中方式（A 乱序 / B 参与者）、覆盖格子、键序与复现次数。
4. 一次探索轮不构成“没有回归”；重构批次仍需 2–3 个落在改动区域的任务轮。
